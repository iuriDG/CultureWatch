# CultureWatch

**Antimicrobial resistance surveillance for a microbiology lab.**
CultureWatch takes laboratory culture results and shows which antibiotics are likely to work for each type of infection, and where resistant bacteria are concentrated or spreading in the hospital.

> ⚠️ **All data is synthetic.** The dataset contains invented patients and results generated by a computer. Results show how the tool works, not the situation in any real hospital. The tool supports guideline-writing and infection control; it does not prescribe for individual patients.

---

## Quick start

For computers that already have **conda**, **Node.js 22+** and **Git**. Otherwise follow the [full setup guide](#full-setup-guide-from-zero) below.

**1. Get the code**

```bash
git clone https://github.com/KalleArtturi/CultureWatch.git
cd CultureWatch
```

**2. Put the dataset in place.** The data is not in Git; it comes from the organisers as `synthetic_microbiology_dataset.zip`. Unzip it **inside the `CultureWatch` folder**:

```bash
unzip ~/Downloads/synthetic_microbiology_dataset.zip -d .     # Mac / Linux, if the zip is in Downloads
```

On Windows, right-click the zip → *Extract All…* and choose the `CultureWatch` folder. The zip already contains the `synthetic_microbiology_dataset` folder, so the result must look like this:

```
CultureWatch/
├── synthetic_microbiology_dataset/
│   ├── patients.csv
│   ├── cultures.csv
│   ├── isolates.csv
│   ├── susceptibility.csv
│   ├── antibiotics.csv
│   └── wards.csv
├── web/
├── api/
└── run_pipeline.py  …
```

Check: `ls synthetic_microbiology_dataset` (Windows: `dir synthetic_microbiology_dataset`) lists the six CSV files. If you see a second `synthetic_microbiology_dataset` folder inside the first, move the inner one up a level.

**3. Python environment and data pipeline**

```bash
conda env create -f environment.yml        # once
conda activate CultureWatch
python run_pipeline.py                     # once, and again whenever the data changes
```

**4. Build the web app**

```bash
cd web && npm install && npm run build && cd ..   # once, and again after changing web code
```

**5. Start it**

```bash
python -m uvicorn api.main:app --port 8000
```

Open **http://localhost:8000**. That's the whole app, in Finnish and English.

**Try it in 30 seconds:** on the start page press **Replay a past outbreak**. The app opens the intensive care unit, plays the weeks before March 2026, and stops when the MRSA alert fires. Then look at **Infection control → Spread** and **Analysis → Antibiogram**.

## Full setup guide (from zero)

About 20 minutes the first time, mostly downloading. Steps 1–8 are done once; after that, see [Everyday use](#everyday-use).

You will need three free tools: **conda** (runs the Python analysis), **Node.js** (builds the web app) and **Git** (gets the code).

### Step 1: Install Miniforge (conda)

Conda manages Python and all the packages this project needs, in an isolated environment. Skip this step if `conda --version` already prints a version number.

**Mac (Apple Silicon: M1/M2/M3/M4).** Open Terminal and run:
```bash
curl -fsSL -o ~/Downloads/Miniforge3.sh https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-MacOSX-arm64.sh
bash ~/Downloads/Miniforge3.sh
```

**Mac (Intel).** Same, but with `x86_64`:
```bash
curl -fsSL -o ~/Downloads/Miniforge3.sh https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-MacOSX-x86_64.sh
bash ~/Downloads/Miniforge3.sh
```
Not sure which Mac you have? Apple menu → About This Mac. "Apple M…" = Apple Silicon.

**Linux:**
```bash
curl -fsSL -o ~/Miniforge3.sh https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
bash ~/Miniforge3.sh
```

During the Mac/Linux installer: press Enter to read the license, type `yes` to accept, keep the default location, and type `yes` when asked to initialize conda. **Then close and reopen your terminal.**

**Windows:** download `Miniforge3-Windows-x86_64.exe` from https://github.com/conda-forge/miniforge/releases/latest, run it with the default options, then open **"Miniforge Prompt"** from the Start menu. Use that window for every command in this guide.

Check it worked:
```bash
conda --version
```

### Step 2: Install Node.js

Node.js builds the web app. You need **version 22 or newer** (20.19 also works). Skip this step if `node --version` already prints `v22` or higher.

- **Mac:** download the macOS installer from https://nodejs.org (the "LTS" button) and run it. With Homebrew you can instead run `brew install node`.
- **Windows:** download the Windows installer from https://nodejs.org and run it with the default options. Then close and reopen Miniforge Prompt.
- **Linux:** follow https://nodejs.org/en/download for your distribution.

Check it worked:
```bash
node --version
npm --version
```

### Step 3: Get the code

You need Git (Mac: run `xcode-select --install` if `git --version` fails; Windows: install from https://git-scm.com).

```bash
git clone https://github.com/KalleArtturi/CultureWatch.git
cd CultureWatch
```

All remaining commands are run **from inside the `CultureWatch` folder**.

### Step 4: Put the dataset in place

The dataset is not in Git. It comes from the organisers as `synthetic_microbiology_dataset.zip`, and it must be unzipped **inside the `CultureWatch` folder**:

- **Mac / Linux** (zip in your Downloads folder, terminal inside `CultureWatch`):
  ```bash
  unzip ~/Downloads/synthetic_microbiology_dataset.zip -d .
  ```
- **Windows:** right-click the zip → *Extract All…* → choose the `CultureWatch` folder.
- **Or by hand:** unzip it anywhere and move the `synthetic_microbiology_dataset` folder into `CultureWatch`.

The zip already contains the `synthetic_microbiology_dataset` folder. The result must be:

```
CultureWatch/
├── synthetic_microbiology_dataset/
│   ├── README.md          (the organisers' description of the data)
│   ├── patients.csv
│   ├── cultures.csv
│   ├── isolates.csv
│   ├── susceptibility.csv
│   ├── antibiotics.csv
│   └── wards.csv
├── web/
├── api/
└── run_pipeline.py  …
```

Check it: `ls synthetic_microbiology_dataset` (Windows: `dir synthetic_microbiology_dataset`) should list the six CSV files. If you see a second `synthetic_microbiology_dataset` folder inside the first, move the inner one up a level. The folder name must be exactly `synthetic_microbiology_dataset`.

The app only reads these files; it never changes them. Imported data goes to `data/imports/` instead.

### Step 5: Create the Python environment

```bash
conda config --set channel_priority strict
conda env create -f environment.yml
```

This installs Python 3.11, pandas, numpy, scipy, matplotlib, JupyterLab, FastAPI and Uvicorn into an environment called `CultureWatch`. It takes a few minutes.

Then activate it:

```bash
conda activate CultureWatch
```

Your prompt should now start with `(CultureWatch)`. **Do this every time you open a new terminal.**

### Step 6: Run the data pipeline

```bash
python run_pipeline.py
```

This takes under a minute and runs four steps in order:

1. **Preprocess:** validates the raw data, joins the tables and applies the first-isolate rule → `data/processed/`
2. **Antibiograms** → `outputs/antibiogram_*.png` and `.csv`
3. **Treatment guide** → `outputs/treatment_guide.csv`
4. **Hospital & trends** → `outputs/hospital_vs_community.csv`, `ward_profile.csv`, `trends.csv`, `alerts_*.csv`

You should see `Pipeline finished` at the end. If validation fails, the pipeline stops and tells you which check failed; nothing is saved.

Re-run this step whenever the raw data or the processing rules change.

### Step 7: Install and build the web app

```bash
cd web
npm install
npm run build
cd ..
```

`npm install` downloads the web app's libraries into `web/node_modules/` (a minute or two, once). `npm run build` checks the code and builds the finished app into `web/dist/` (a few seconds). Neither folder goes into Git.

### Step 8: Start the app

```bash
python -m uvicorn api.main:app --port 8000
```

Open **http://localhost:8000**. When the terminal shows `Application startup complete`, the app is ready.

- **Stop it:** press `Ctrl+C` in the terminal.
- **The first page takes a few seconds** while the data loads into memory; after that pages open in about a second.
- Use `python -m uvicorn`, not plain `uvicorn`: it makes sure the environment's own Python runs the app. A plain `uvicorn` can pick up another Python on the computer and fail with "No module named 'pandas'".

### Step 9: Check that it works

1. Choose your ward on the start page, or press **Replay a past outbreak**: the intensive care unit should turn red in March 2026 with "3 new MRSA cases in 4 weeks, usually about 0.1".
2. In a second terminal (with `conda activate CultureWatch`), check every number against the raw files:

   ```bash
   python verify_numbers.py
   ```

   It should end with `31/31 numbers match the raw data.`

That's it. 🎉

## Everyday use

After the one-time setup, starting the app is just:

```bash
cd CultureWatch
conda activate CultureWatch
python -m uvicorn api.main:app --port 8000
```

and opening http://localhost:8000.

Only when something changed:

| You changed... | Run first |
|---|---|
| the raw data or the processing rules | `python run_pipeline.py` |
| code in `web/` (or pulled new web code) | `cd web && npm install && npm run build && cd ..` |
| `environment.yml` | `conda env update -f environment.yml --prune` |

### Working on the web app (live reload)

While changing web code, use two terminals instead, so the page updates as you save:

```bash
# terminal 1: the API, reloading when Python files change
python -m uvicorn api.main:app --reload --port 8000

# terminal 2: the web app in development mode
cd web
npm run dev
```

Open **http://localhost:5173**. Development mode is slower than the built app (React deliberately sends each request twice to catch bugs), so **demo from http://localhost:8000**, after `npm run build`. The API's own documentation is at http://localhost:8000/docs.

### Before a demo

1. Build the latest version: `cd web && npm run build && cd ..`, then start the app (Step 8).
2. Press **Replay a past outbreak** once. Each replayed week is calculated the first time and remembered after that, so the second run in front of the jury is fast.
3. To show the import live: `python make_demo_batch.py` prepares real data cut at 23 Feb 2026 (see [web/README.md](web/README.md)). Press **Restore original dataset** afterwards.

### Share it on phones

The app on port 8000 can be opened from any device through a temporary public link:

```bash
cloudflared tunnel --url http://localhost:8000       # prints a public https://….trycloudflare.com link
```

Open the printed link on any device. It works only while the app and the tunnel run, and changes every time the tunnel restarts. Anyone with the link can view the app, but importing data only works on the computer running it. (Install cloudflared: `winget install Cloudflare.cloudflared` or `brew install cloudflared`. The **Share / Jaa** QR button is hidden for now; set `SHOW_SHARE = true` in `web/src/App.tsx` to bring it back.)

## What you get

**A web app** (`web/`, Finnish and English) built around the people who use it: ward staff, the infection unit and lab scientists. Every feature is listed below.

### Web app: every feature in plain words

The tabs are grouped by who uses them: **My ward** (ward staff), **Infection control** (the infection unit), **Lab** (lab scientists) and **Analysis** (everyone writing guidelines). **Import** and **Methods** sit on the right of the tab bar.

| Where | Feature | What it does for you |
|---|---|---|
| **My ward** | Own-ward view | Opens on your own ward. A short summary in everyday words, then: anything unusual **in the last 4 weeks** (alerts), and is resistance **worse than last year or than the rest of the hospital** (signals). |
| **Infection control** | Findings | The infection unit's daily to-do list: every new resistant bacterium (MRSA, ESBL, VRE, CPE), whether the patient is a **new or known carrier**, where the patient was before, and tick-boxes for who has been told. Searchable, export as a line list. |
| | Alerts | All wards at once: which have more cases than normal right now, plus every past alert. |
| | Spread | **Where new carriers had been in the 30 days before their finding**, as a flow chart from ward to ward. Each ward has its own colour; hover a ward or band to highlight its flows. A lead for infection control, not proof of transmission. |
| | Weekly summary | One printable page for the infection unit: wards on alert and new resistant findings from the last 7 days. |
| **Analysis** | Hospital | The big picture: totals, ward hotspots, resistance **by the patient's home area**, hospital vs outpatient resistance. |
| | Antibiogram | Colour table: how often each antibiotic fails against each bacterium. Download as CSV or **print / save as PDF** as a one-page cumulative antibiogram. |
| | Treatment guide | For an infection type, which antibiotic would have worked for most past patients. |
| | Trends | Is resistance rising? The chart comes first; below it the **guideline expiry date**: when a common antibiotic crosses the 20% line where doctors stop starting it before the lab result. |
| Top right | Import | Upload new lab results as CSV files. Every file is checked first (the pipeline's 16 data checks); nothing changes unless all checks pass, and the original data can always be restored. |
| | Methods | Every rule and calculation, written out, plus how a resistant finding is handled. |
| Top bar | **Quick search** | Type a ward, bacterium, antibiotic, resistance type or patient ID (press `/` to start). **The answer shows in the list right away**, e.g. *E. coli + trimethoprim: 20.1% resistant in the last 12 months · over the limit since ~Jan 2026*, *ICU: no alert now · MRSA 19.7%*, *P003612: new MRSA carrier, 7 Mar 2026*. Enter opens the full view. Works in Finnish too (*teho*, *trimetopriimi*). |
| | **Copy link** | Every view has its own address with its filters (e.g. `#/antibiogram?specimen=urine&time=4w`, `#/trends?org=Escherichia+coli&ab=TMP`). Copy link, bookmark or share it, and it reopens exactly the same view. |
| | **Historical replay** | Rewind to any week and press Play: the whole app shows what it would have shown that day. **Replay a past outbreak** on the start page opens the clearest outbreak in the data (ICU, MRSA, March 2026) and plays until the alert fires. |
| | Custom dates | Every period choice (Hospital, Antibiogram, Treatment guide, Findings, Spread) also has **Custom dates**: pick any From and To day. Each patient's bacterium still counts once within the chosen dates. |
| | FI / EN | The whole app in Finnish and English, with Finnish number and date formats. |
| | Logo | Back to the start page. |
| Everywhere | Tables for real volumes | Every table shows 25 rows per page; sorting and search work across all rows. Filters beyond time and specimen sit behind **More filters**. Works on phones. |
| | Verified numbers | `verify_numbers.py` recomputes the numbers from the raw files with separate code and compares them with the app (34/34 match), including spread, home areas, the weekly summary, custom date ranges and the quick-search answers. |

The **Share / Jaa** QR code is built in but hidden for now (`SHOW_SHARE` in `web/src/App.tsx`).

How to run it: see [Quick start](#quick-start) above. A plain-language guide to the web app is in [web/README.md](web/README.md).

## Project structure

```
CultureWatch/
├── README.md                         ← this file
├── environment.yml                   ← Python packages for conda
├── .gitignore
├── synthetic_microbiology_dataset/   ← raw CSVs (never edited, not in Git)
├── data/                             ← created locally, not in Git
│   ├── processed/                    ←   tables made by the pipeline
│   ├── imports/                      ←   CSV imports (staged files, the imported data in use)
│   └── demo_batch/                   ←   real data split for the import demo (make_demo_batch.py)
├── outputs/                          ← charts and tables from the pipeline (not in Git)
│
├── run_pipeline.py                   ← runs the four steps below in order
├── preprocess.py                     ← step 1: validate, join, first-isolate rule
├── cw_utils.py                       ← shared helpers: filters, rolling windows, resistance %, confidence intervals
├── antibiogram.py                    ← step 2: antibiogram tables and heatmaps
├── treatment_guide.py                ← step 3: antibiotic coverage per infection scenario
├── hospital_trends.py                ← step 4: hospital vs community, wards, trends, alerts, carriers, expiry dates
│
├── api/                              ← small Python API used by the web app
│   ├── main.py                       ←   every endpoint; calls the analysis files above
│   └── importer.py                   ←   CSV import: stage, check, apply, restore
├── web/                              ← the web app (React + TypeScript), see web/README.md
│
├── verify_numbers.py                 ← independent check of the numbers against the raw files
└── make_demo_batch.py                ← splits the real data for the import demo
```

**How the pieces connect:** `preprocess.py` turns the raw CSVs into `data/processed/`. Every analysis file imports `cw_utils.py` and reads `data/processed/`. The web app reaches them through `api/` and shows their results. Because all rules live in one place (`cw_utils.py` and `preprocess.py`), every view produces the same numbers.

Each analysis file can also be run on its own, e.g. `python antibiogram.py`.

## Security and privacy

- **No secrets.** The app uses no API keys, passwords or accounts, and none are stored in the code or the Git history. `.gitignore` also keeps `.env`, key files, the dataset and all generated data out of Git.
- **Runs on your computer.** The API listens only on this computer (`127.0.0.1`), not on the network.
- **The public link is view-only.** Through the shared link (Cloudflare tunnel) people can look, but importing or restoring data is refused. Data can only be changed from the app itself on the computer running it; requests from other web sites or tricked browsers are refused too (the app sends its own header, and host names are checked).
- **Safe downloads.** Exported CSV files neutralise cells that a spreadsheet could run as a formula.
- **Browser protections.** Every page is served with security headers (content security policy, no framing, no sniffing).
- **Only synthetic data.** The dataset is invented. **Never put real patient data behind the public link.** Real use would need the hospital network, user login, HTTPS and audit logging.

## Key definitions

| Term | Definition used in CultureWatch |
|---|---|
| **First isolate** | Only the first isolate per patient, per organism, per specimen type, per 12-month period counts. Prevents repeatedly tested patients from skewing results. |
| **Period** | 12-month surveillance years from October to September: Y1 (2023/24), Y2 (2024/25), Y3 (2025/26). |
| **Minimum 30** | A resistance % is shown only when based on at least 30 isolates; otherwise "n<30". |
| **IR (intrinsic resistance)** | Natural resistance, not shown as a %: Klebsiella and Citrobacter – ampicillin; Proteus mirabilis – nitrofurantoin. |
| **Hospital-onset** | Sample taken on day 3 or later of the hospital stay. |
| **Community** | Outpatients: health centres and the emergency department. |
| **Coverage** | Share of all infections in a scenario that an antibiotic would have treated, accounting for which bacteria cause them. |
| **Colours** | Green <10% resistant, amber 10–20%, red >20%. |
| **ESBL / MRSA / VRE / CPE** | Resistance types tracked by infection control: ESBL in E. coli and Klebsiella, MRSA in S. aureus (cefoxitin screen), VRE in Enterococcus, CPE in Enterobacterales. |

Statistical methods (Wilson confidence intervals, Fisher's exact test, Cochran–Armitage trend test, Poisson cluster detection) are described in the app's **Methods** tab.

## Troubleshooting

**`conda: command not found`**
Close and reopen the terminal. On Windows, use "Miniforge Prompt", not the regular Command Prompt.

**`ModuleNotFoundError: No module named ...`**
The environment isn't active. Run `conda activate CultureWatch`. If it still fails, update the environment: `conda env update -f environment.yml --prune`.

**`FileNotFoundError: ... processed/ast_joined.csv`**
The pipeline hasn't been run yet, or you're in the wrong folder. Make sure you're inside `CultureWatch`, then run `python run_pipeline.py`.

**`FileNotFoundError: ... synthetic_microbiology_dataset/...`**
The dataset is missing or in the wrong place. See Step 4.

**`PIPELINE STOPPED ... DataValidationError`**
The raw data failed a quality check. The message lists which checks failed. Fix or replace the raw files and run again.

**`CondaValueError: prefix already exists`** (during Step 5)
The environment already exists. Update it instead: `conda env update -f environment.yml --prune`.

**Code changes don't show up**
Restart the API (`Ctrl+C`, then start it again) or use `--reload` (see *Working on the web app*); rebuild the web app after changing `web/`. In JupyterLab, restart the kernel (Kernel → Restart Kernel), because imported files are only read once per session.

**`No module named 'pandas'` when starting the API**
You ran plain `uvicorn`, which used another Python installation. Run `python -m uvicorn api.main:app --port 8000` with the environment active.

**http://localhost:8000 says `{"detail":"Not Found"}`**
The web app hasn't been built. Run `cd web && npm run build && cd ..`, then restart the API.

**Every page says "Cannot reach the API"**
The API isn't running (start it, Step 8). In development mode (port 5173), stop `npm run dev` with `Ctrl+C` and start it again: it forwards requests to the API only if it was started with `web/vite.config.ts` in place.

**`npm: command not found`, or `npm run build` complains about the Node version**
Install or update Node.js (Step 2), then close and reopen the terminal.

**Port 8000 already in use**
The app is already running in another terminal. Use that one, or stop it with `Ctrl+C`.

**Mac: everything is slow**
You may have installed the Intel version of Miniforge on an Apple Silicon Mac. Run `conda info`; the platform line should say `osx-arm64`. If it says `osx-64`, uninstall and reinstall using the Apple Silicon link.

## Working on the code (team workflow)

- **Work on your own branch** and merge into `main` when your piece works:
  ```bash
  git checkout -b my-feature
  # ...make changes...
  git add .
  git commit -m "Describe the change"
  git push -u origin my-feature
  ```
- **Before pushing to `main`, pull first** to avoid "rejected" errors:
  ```bash
  git pull --rebase origin main
  ```
- **Never edit the same Jupyter notebook as someone else.** Notebooks are hard to merge in Git. Move finished logic into `.py` files.
- **Change rules in one place only:** resistance calculations and filters in `cw_utils.py`, data processing in `preprocess.py`. If you change preprocessing in the notebook, copy the change into `preprocess.py` too.
- **Adding a package:** add it to `environment.yml`, run `conda env update -f environment.yml --prune`, and commit the file so everyone gets it.

## Uninstalling

Remove just this environment:
```bash
conda env remove -n CultureWatch
```

The web app's libraries live only inside the project (`web/node_modules/`), so deleting the `CultureWatch` folder removes them too. Node.js itself is uninstalled like any other program.

Remove Miniforge completely (Mac/Linux):
```bash
conda init --reverse
rm -rf ~/miniforge3 ~/.condarc ~/.conda
```
Windows: Settings → Apps → Miniforge3 → Uninstall.

## Data sources and basis

The synthetic dataset (10,000 patients, 46,792 cultures, 24,571 isolates, 172,381 susceptibility results, Oct 2023 – Sep 2026) was generated from rules and probabilities. Resistance levels for E. coli, ESBL and MRSA are roughly calibrated to the Finnish Finres 2023 report (THL); intrinsic resistances follow EUCAST Expected Resistant Phenotypes v1.2. See the dataset's own README for details.

Stewardship tiers and coverage targets in the Treatment Guide are illustrative and should be reviewed against local guidelines (e.g. Käypä hoito) before any real-world use.
